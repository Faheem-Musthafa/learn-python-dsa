# 03 - UX Research and Requirements
Scope: static site, no accounts, no backend, progress in localStorage, ages 10 to adult, Python + DSA, step-through animations, Pyodide editor.
Evidence tags: **[V]** verified on a fetched page (URL in section 9). **[M]** from memory or my judgement, not re-verified. **[REQ]** a requirement for the build.

## 0. Ten decisions that matter most
1. **Weekly rhythm, not a daily streak.** Goal = N study days per week (user picks 1-7, default 3). Misses never reset a number to zero. See 5.2.
2. **No lives, hearts or timers.** Mistakes cost nothing. Errors are teaching moments.
3. **Mastery per topic with four labelled states** (Khan model), shown by shape + text, never color alone. Mastery can become "Due for a refresher", never "lost".
4. **Recommend, don't lock.** Course map suggests one "Continue" step but every node is openable (Khan and NeetCode both let you roam) [V].
5. **Animation player = native controls + one scrubber + one sentence of narration per step**, arrow-key stepping, autoplay OFF, respects reduced motion.
6. **Editor = CodeMirror 6** (touch + a11y), not Monaco. Pyodide in a Web Worker, lazy-loaded. Errors rewritten in plain words with the real traceback one click away.
7. **Hint ladder with an explicit, guilt-free "show solution"** that opens beside the learner's code, never over it.
8. **Export/import JSON is a first-class feature, not buried.** Safari deletes localStorage after 7 days without a visit [V]. Backup nudges are required.
9. **Recommended visual direction: "Workshop"** (warm paper, ink, tactile sticker shapes) with a first-class dark theme.
10. **WCAG 2.2 AA is the floor**; 44px touch targets on phones; text-spacing overrides must not break layout.

Patterns that win across products: (a) one clear next step, (b) code typed within the first minute, (c) tiny units (5-10 min), (d) mastery state per topic, (e) stepper controls with keyboard parity, (f) hints that point rather than tell.

## 2. Information architecture
Top-level nav (5 items, bottom bar on phone, top bar on desktop): **Learn** (course map), **Practice**, **Review**, **Progress**, **More** (glossary, search, settings, help). Search is a persistent icon, not a tab.

URL pattern (static, shareable, works with hash/history): `/learn`, `/learn/{unit}/{lesson}`, `/practice`, `/practice/{id}`, `/review`, `/progress`, `/glossary#term`, `/search?q=`, `/settings`, `/playground`.

### 2.1 Home / Continue
- One big **Continue** card: lesson title, "step 3 of 7", ~6 min. Beneath: "Review due today (4)", weekly rhythm ring.
- First visit: three choices only: "I'm new to coding", "I know some Python" (jump to Python checkpoint), "Show me algorithms". No account, no age question.
- Empty state friendly; no marketing walls.

### 2.2 Course map (`/learn`)
- **Two views, toggle remembered:**
  - **Path view** (default, phone-first): vertical spine, units as sections with a name and a "you will be able to..." line, lessons as nodes.
  - **Graph view** (DSA only, desktop and tablet): prerequisite graph à la NeetCode [V]; phones fall back to a grouped list with "needs: X" chips.
- Node states, each shape + label + icon (not color only): Not started (empty circle), In progress (half), Done (check), Solid (filled + star), Due for refresher (circular arrow). Current recommended node has a pulsing-free outline and "Start here" text.
- Unit header shows mastery rollup "5 of 8 topics solid".
- Locks: none. Soft note on far-ahead nodes: "Works best after Loops. Open anyway".
- Checkpoints ("Already know this? Skip check", 5 questions) at unit heads so the experienced can leap; passing marks topics Familiar, not Mastered.
- Must work: keyboard (arrow through nodes), screen reader (list of links with state text), 200% zoom.

### 2.3 Lesson page (`/learn/{unit}/{lesson}`) - details in section 3
Goal line, progress dots, chunked content, animation, "Try it" editor, 2-3 check questions, summary, next. Bookmark and note buttons in the header toolbar.

### 2.4 Practice (`/practice`)
- Browse by topic, difficulty (3 levels with names: Warm-up, Core, Stretch), and status. Filters: topic, "unsolved", "bookmarked", "has animation".
- Each item: title, topic chips, difficulty, status icon, ~minutes. No "acceptance rate" or ranking numbers.
- Item page = problem statement + editor + tests + hint ladder (4.x). "Twin problem" link after a solution reveal.
- Mixed practice mode: "Surprise me" (5 questions from topics you've started), no timer by default; timer is an opt-in toggle for teens/adults.

### 2.5 Progress dashboard (`/progress`) - full spec in section 5
### 2.6 Review queue (`/review`)
- Session = max 8 items by default (setting 5-15). Shows "about N minutes".
- Items are mini-questions (retrieval first, then reveal), grade buttons are plain: "Got it", "Almost", "Not yet" (feeds scheduler; learning-science agent owns algorithm).
- Done state: "You've finished today's review. Nothing else due." with no upsell to do more. Optional "Keep going" button shows extra, labelled optional.
- Backlog: if more than 20 due, collapse to "Catch-up: we picked the 8 most useful" and quietly snooze the rest. Never show an overdue count in red.

### 2.7 Glossary (`/glossary`)
- A-Z list, filter box, each entry: one-sentence kid-safe definition, tiny example, "see in lessons" links, "Say it simply / Technical" toggle.
- Inline terms in lessons: dotted underline; **tap or Enter opens a popover** (not hover-only; WCAG 1.4.13 content on hover or focus) with Esc to dismiss.

### 2.8 Search
- Client-side static index (Pagefind or equivalent). Searches lessons, glossary, practice titles, user notes. Open with `/` (focus-only, see 3.5) and Ctrl/Cmd+K, and a visible icon.
- Result groups by type; typo tolerance; recent searches stored locally; empty state suggests glossary.

### 2.9 Settings (`/settings`)
Grouped, saved instantly, with a "Reset to defaults" and live preview:
- **Look:** theme (System/Light/Dark), text size (100/115/130/150%), reading font (Default / Atkinson Hyperlegible / Lexend), spacing ("Roomy" = BDA-style spacing), high contrast.
- **Motion and sound:** Reduce motion (Auto/On/Off), animation default speed, autoplay (default off), sounds (default off), celebrations (Full/Quiet/Off).
- **Keyboard:** shortcuts on/off (WCAG 2.1.4), shortcut list.
- **Editor:** font size, tab size 4, auto-close brackets, symbol bar (phone), show line numbers.
- **Rhythm:** weekly goal, pause mode ("I'm on a break until...").
- **Your data:** export JSON, import JSON, last backup date, backup reminder (off/monthly), delete everything with type-to-confirm. Statement: "Everything stays on this device."

## 3. Lesson page UX
### 3.1 Reading column
- Single column, `max-width: 65ch` body (BDA 60-70 chars [V]; Dyslexia Scotland 50-75 [V]), body 18px desktop / 17px phone minimum, line-height 1.6, left aligned, no justification, no italics for emphasis (bold instead) [V].
- Paragraphs <= 4 lines on phone, sentences <= 20-25 words [V Dyslexia Scotland: up to 25]. One idea per chunk, <= ~120 words between interactions.
- Headings: h2 only for chunk titles that are questions or goals ("What does a loop do?"). Heading scale >= 1.2x the body [V BDA].
- Left rail on desktop: lesson outline (sticky, collapsible). On phone: a progress bar + "step 3 of 7" at top; outline in a sheet.
- A **"Big idea" callout** (max 1 per lesson) and **"Careful!" callout** for common mistakes. Callouts carry an icon + word, not just a color.
- Lesson footer: "What you can do now" 3 can-do bullets; ticking the "Got it" button marks complete; "Next: X" is the primary button.

### 3.2 Code blocks
- Mono 15-16px (never < 14px), line-height 1.5, theme-aware, tab size 4. Horizontal scroll **never wraps by default** (wrap breaks indentation meaning), with a visible scroll shadow and a "Wrap lines" toggle.
- **Authoring lint:** lesson snippets <= 40 chars/line for phone fit, <= 80 on desktop; <= 12 lines per inline block.
- Per block: Copy, "Open in editor" (sends it to the Try-it pane), optional "Run" for read-only runnable snippets. Buttons >= 44px on phone, 32px desktop (>= 24 minimum per WCAG 2.5.8 [V]).
- Highlight lines by background tint **plus** a left bar and line-number weight, so it's not color-only. Linked highlight: the line being narrated in the animation highlights in the code block.
- Indentation shown with faint guides; spaces never rendered as visible dots unless toggled.
- Provide `aria-label` ("Python code, 6 lines") and let screen readers read it as plain text (no per-token spans announced).

### 3.3 Animation player (the DSA centerpiece)
**Anatomy (top to bottom):** Title + "step 7 of 24" -> Stage (the visualization) -> Narration caption -> Control bar -> Scrubber -> Secondary row (speed, code toggle, "Predict" toggle, reset input). Code pane is beside the stage on desktop, below it in a tab on phone.

**Controls, in order, with names a 10-year-old understands** (icon + text label at desktop, icon + accessible name on phone):
1. Restart (|<)  2. Back (<)  3. **Play / Pause** (primary, largest, 56px)  4. Next (>)  5. End (>|)
- Scrubber: native `<input type="range">`, `min=0, max=steps`, `aria-valuetext="Step 7 of 24: comparing 5 and 3"`; tick marks at "key moments" (swap, found, done) so learners jump to interesting steps. Pointer drag is never the only path; arrow keys on the slider work, satisfying WCAG 2.5.7 dragging alternatives [V: criterion list].
- Speed: 3-5 stops as a segmented control, 0.5x, 1x, 2x (labels, not a tiny slider). Default 1x = about 1.2 s/step; reduced-motion users get 0.5x and **no tween between steps** (instant state change + highlight).
- Step counter always visible. When the animation ends, Play becomes **Replay** with a "Try with your own numbers" button.
- Rewind must be exact: the engine precomputes a step list (state snapshots) so Back and scrub are free and deterministic. [REQ]
- Autoplay never starts on page load. WCAG 2.2.2: anything moving > 5 s must be pausable [V]; our player is pause-by-default, satisfying it.

**Desktop layout (>= 1024px):**
```
+--------------------------+----------------------+
| Reading column (65ch)    | Sticky Stage panel   |
| ...text...               |  [ stage viz       ] |
|                          |  caption: "Compare 5 |
|                          |  and 3. 5 is bigger" |
|                          |  |< <  [Play]  > >|  |
|                          |  ====o=========  7/24|
|                          |  Speed 0.5 1x 2x  [<>]|
+--------------------------+----------------------+
```
Stage and code sit side by side when the reading column is collapsed ("Focus mode"). Sticky panel stays in view while the text scrolls.

**Phone layout (< 640px):** the stage is **inline** in the flow (not sticky; a sticky 45vh stage eats the reading space and collides with the keyboard), with this order: stage -> caption -> controls. A "Full screen" button opens a focus sheet: stage on top, code tab / narration tab, controls pinned to the bottom thumb zone, rotates to landscape side-by-side. Control bar: 5 buttons, each >= 48x48px with 8px gaps in one row; scrubber on its own full-width row below; speed in a third row. Safe-area insets respected.

**Narration placement**
- A visible **caption** directly under the stage, 18px, one sentence per step ("Compare 5 and 3. 5 is bigger, so swap."), prefixed by step number. Never overlaid on the stage (covers content, fails contrast on moving backgrounds).
- Also mirrored into an `aria-live="polite"` region, but only on user-initiated step changes or pause; during autoplay, announce nothing except a final "Done" [REQ]. Settings: "Read steps aloud" off by default.
- Optional "Why?" disclosure under the caption for the deeper reason. Optional text-to-speech via the Web Speech API is a settings toggle, off by default [M].
- Highlighting uses color + shape + label (e.g. compared bars get a bracket and the word "comparing"), consistent legend across all animations.
- **Predict mode** (toggle): before revealing the next step, ask "What will happen next?" with 2-3 big buttons; wrong guesses just show the real step (no penalty). The learning-science agent owns the pedagogy; UI hook is reserved.

### 3.4 Interaction between animation and code
- Highlighting current code line in lockstep; clicking a code line seeks to the first step that executes it.
- "Edit the input" field (array/graph) beneath the stage: validate and rebuild step list; cap sizes (e.g. 12 items) with a friendly message.
- Variables panel (Python Tutor-style boxes) for Python lessons: name, value, changed-this-step flash only if motion allowed [V concept; exact UI M].

### 3.5 Keyboard shortcuts (active only while the player or lesson has focus; global ones need a modifier)
| Key | Action |
|---|---|
| Space or K | Play / Pause (when focus is not on another button/input) |
| Left / Right | Step back / forward |
| Shift+Left / Right | Back/forward 5 steps |
| Home / End | First / last step |
| Up / Down or - / + | Speed down / up |
| R | Replay |
| C | Toggle code pane |
| ? | Show shortcuts |
| Ctrl/Cmd+Enter | Run code (in editor) |
| Ctrl/Cmd+K | Search |
| Esc | Close popover/sheet; leave editor (see 4.6) |

WCAG 2.1.4 requires single-character shortcuts to be turnable off, remappable, or active only on focus [V]. Decision: player shortcuts fire **only when the player container has focus**, plus a Settings master toggle. `/` for search also obeys the toggle. Shortcuts never fire while typing in the editor or any input. Show a "Keyboard" button in the player that opens the cheat sheet.

## 4. In-browser Python editor UX (beginners)
### 4.1 Loading Pyodide [REQ]
- Lazy-load only when the learner reaches/clicks the editor. Run in a **Web Worker** so the UI never freezes and **Stop** can terminate the worker (SharedArrayBuffer interrupt needs COOP/COEP headers a static host may not provide [M - verify with chosen host]).
- State machine messaging, plain words: "Getting Python ready... (first time takes a few seconds, then it's saved on your device)" with a real progress bar if possible. Reading and animations stay usable meanwhile. Offline notice if the fetch fails, with Retry.
- Keep a **fake "run"** fallback for lessons: pre-captured outputs so the lesson can't dead-end if Pyodide fails.

### 4.2 Layout and run controls
- Desktop: editor left, output right; Phone: editor on top, output panel below that auto-scrolls into view on Run; tabs "Code | Output" only on very small heights.
- **Run** is the primary button, labelled "Run" with a play icon, top-right of the editor, also Ctrl/Cmd+Enter. On phone it's a floating bar pinned **above the keyboard** (use `visualViewport` to track), with Run, Undo, Redo, and a "Hint" button.
- States: Ready -> Running (spinner + **Stop** button after 2 s; "Still running. Stop it?" after 5 s, because an accidental `while True` is the #1 beginner hang) -> Done ("Finished in 0.1 s") or Problem.
- Output panel labelled "What your program printed". Clear output only on the next Run, never on edit.
- **Reset**: "Start over" with a confirm that offers "Undo reset" for 10 s (toast), because kids hit it by accident. Restores the starter code; the previous code is kept in a "Previous versions" list (last 5).
- Autosave code per exercise to localStorage (debounced); restore with a banner "Welcome back, your code is saved".

### 4.3 Phone input specifics
- CodeMirror 6 (touch-friendly, a11y-first) rather than Monaco; Monaco has documented keyboard-trap issues and isn't built for mobile [V keyboard trap thread; mobile claim M].
- Attributes: `autocapitalize="off" autocorrect="off" spellcheck="false" inputmode="text"`; no smart quotes.
- **Symbol bar** above the on-screen keyboard: `Tab/indent`, `( )`, `[ ]`, `{ }`, `" '`, `:`, `=`, `_`, `#`, `.`, `,`. Buttons 44px wide. Long-press not required.
- Auto-indent after `:` and auto-close brackets/quotes (toggle in Settings). Visible whitespace guide so indentation errors are seeable.
- Pinch zoom stays enabled. Font size setting 14-22px.

### 4.4 Friendly errors
Two layers: **a plain-words card** and **"Show Python's exact message"** disclosure (learners must eventually read real tracebacks). Always highlight the offending line in the editor (background + gutter marker + text "line 4").

Card template: **What happened -> Where -> Common cause -> Try this**. Neutral voice: "Python got confused on line 4", never "You made an error".

| Python error | Plain explanation + suggestion |
|---|---|
| SyntaxError (missing colon / bracket / quote) | "Python couldn't understand this line. Lines like `if`, `for`, `def` end with a colon `:`. Check the end of line 4." |
| IndentationError | "Python uses spaces at the start of a line to group code. Line 5 is lined up differently from line 4." |
| NameError | "Python doesn't know the name `scoer` yet. Did you mean `score`? Names must be created before they're used." (suggest nearest by edit distance) |
| TypeError (str + int) | "You tried to add words and a number. Try `str(5)` or `int("5")`." |
| IndexError | "The list has 3 items (positions 0, 1, 2) but you asked for position 3." |
| KeyError | "The dictionary doesn't have the key `'cat'`." |
| ZeroDivisionError | "You can't divide by zero. Check what the number below the `/` is." |
| Infinite loop timeout | "Your program is still running. A loop may never end. Stop it and look at the loop's condition." |
| Wrong answer (tests) | Show first failing case: input -> expected -> your result; hide the rest behind "See other tests". |

Rules: errors never touch progress or stats; no red-only signalling (icon + word); no shaking/buzzer; no sound by default.

### 4.5 Hints and answers without spoiling
**Ladder (each step is a user click, never automatic):**
1. **Nudge** - a question that refocuses ("What should happen when the list is empty?").
2. **Approach** - names the idea/tool in words, links glossary/docs (Exercism rule: point to resources, don't spell out the solution [V]).
3. **Skeleton** - code with blanks `____`.
4. **Show a solution** - after a gentle confirm: "Want to see one way to solve it? You can still try again after." No time or attempt gate (gates feel punitive and Exercism has none [V]); but we *do* show it:
   - in a **separate panel beside the learner's code** (never replacing it), with line-by-line explanation and "compare with mine" diff;
   - rendered with `hidden`/`<details>`, **not CSS blur**, so screen readers and "view source" skimmers don't get it by accident;
   - the item gets a quiet "Saw a solution" tag and a **twin problem** offer; mastery credit needs the twin (stated kindly: "Try a fresh one to lock it in").
- Progressive disclosure also within a hint: collapsed by default; remember opened levels per exercise.
- "I'm stuck" is one button with a menu ("Show a hint", "Explain my error", "See a walkthrough"), not three scattered links.
- Solved state: celebratory but brief (2 s), then "Want to see a neater way?" (alternate solutions after success are the safest spoiler).

### 4.6 Keyboard accessibility of the editor
CodeMirror does not capture Tab by default; capturing it creates a WCAG "no keyboard trap" risk [V codemirror.net tab example]. Decision: indent with Tab (beginners expect it) **and** a documented escape: "Press Esc, then Tab to move on", shown as a small persistent hint under the editor and in the shortcuts sheet; plus a Settings toggle "Tab moves focus instead of indenting".

## 5. Personal tracker spec
Principles: show **what I can do and what I did**, never what I "owe". Everything computed from a local event log. No comparisons with other people (impossible and undesirable).

### 5.1 Stats: keep vs cut
| Motivates (keep) | Distracts (cut or demote) |
|---|---|
| Topic mastery map (what I can do) | Total XP / points (inflation, meaningless) |
| Days studied this week vs my own goal | Big current-streak number as the hero |
| Total study days (never resets) | Leaderboards, ranks, percentiles |
| Longest run (kept forever) | "Streak lost!" states, red zeros |
| Practice solved by topic | Minutes-studied as a goal (rewards dawdling [M]) |
| "New this week" can-do list | Accuracy % per session (punishes exploration) |
| Review items retained | Hearts, timers, speed rankings |

Time studied is shown but secondary: **active** minutes only (page visible + input in the last 60 s; idle capped). Duolingo itself moved to a quality-weighted time metric instead of raw time [V]; copy the idea: don't count animation-autoplay-while-away.

### 5.2 Streak design: "Weekly rhythm"
- Unit = **a study day** (any lesson step, review set, or practice attempt qualifies - low bar, 5 minutes).
- Goal: **N days per week** (default 3; options 1-7). The ring fills toward N; any days count; no need for consecutive days.
- Primary number is the **week ring** ("2 of 3 days this week"). Secondary: **"Weeks in a row you met your goal"**; if a week is missed, it shows "Last time: 5 weeks. Start a new run anytime", *not* "0".
- Permanent, non-resetting counters beside it: **Total study days** and **Longest run**. These only go up, so there is no loss to protect.
- **Rest built in:** the rest of the week is the freeze. Plus **Pause mode** ("holiday until 12 Jan") that freezes the run with a friendly "See you after your break". No currency, no purchasable freezes, no repair offers (Duolingo's streak repair/freeze mechanics are monetized and anxiety-linked [V critique]).
- Copy bank: "Welcome back!", "Nice, that's day 2 this week", "Rest is part of learning". Banned: "You lost", "Don't break", "Keep your streak alive!", "Your streak is in danger", any mascot disappointment [V recommendations D3, D4].
- Celebration is tied to **learning events** (finished a topic, solved a Stretch problem), not only to the number ticking up. Milestone pops: small, skippable, off in "Quiet" mode. (Duolingo's streak animation lifted 7-day retention +1.7% [V], so brief delight works; keep it brief.)
- Welcome-back after a gap: say what they can do now and offer a 3-question warm-up, not a guilt screen.

### 5.3 Dashboard layout (`/progress`)
Top to bottom on phone; 2-column grid on desktop:
1. **Header:** "Hi {nickname}" (optional local name), Continue button.
2. **Weekly rhythm ring** (7 dots Mon-Sun, filled = studied; today outlined; goal marker). Text under it repeats the data.
3. **Mastery map** (5.5).
4. **Activity heatmap** (5.4).
5. **Time this week** small bar chart, active minutes per day, axis labelled, optional.
6. **Goals** (5.7).
7. **Notes and bookmarks** (5.6).
8. **Backup card** (5.8) - elevated when overdue.
Every chart has a text equivalent and "View as table".

### 5.4 Activity heatmap
- 12 weeks desktop (columns = weeks, rows = Mon-Sun), 8 weeks on phone (cells >= 20px); week start follows setting.
- 5 intensity steps from **actions that count** (steps completed + problems attempted), thresholds: 0, 1-2, 3-5, 6-10, 11+. Empty = neutral outlined cell (never red/grey-shaming); single-hue ramp, all steps with a 1px outline so the lightest step still reads (WCAG 1.4.11 non-text contrast 3:1 for the cell boundary vs the background).
- Cells are not the only path to data: tap/Enter on a cell opens a text line below ("Tue 14 Oct: 2 lessons, 3 problems, 18 min"). The grid is a roving-tabindex `role="grid"` or a table for SR.
- Legend: "Less -> More" with the 5 swatches. No "longest gap" metric.

### 5.5 Mastery per topic
- Rows = topics grouped by unit, each with a 4-state meter:
  - **Not started** (empty ring)
  - **Practising** (quarter ring)
  - **Solid** (three-quarter ring)
  - **Mastered** (full ring + check)
  Plus **Due for a refresher** (circular arrow badge) when review is overdue - tone "A quick refresher helps this stick".
- State rules shown in a "How does this work?" popover in one sentence each (Khan's thresholds are the template: 70% / 100% / mixed review [V]); the algorithm itself is the learning-science agent's.
- Unit rollup "5 of 8 solid or better". Count Solid+Mastered toward course % (Khan counts Proficient+Mastered only [V]).
- Tap a topic -> side panel: lessons done, problems solved, last practiced, "Practice this" and "Review this" buttons.
- Sort/filter: "Needs a refresher", "Not started". Default view is by course order.

### 5.6 Notes and bookmarks
- Bookmark icon in lesson and practice headers (toggle, 44px). "Saved" list on Progress with topic and date.
- Per-lesson **My note**: plain textarea, autosave, 2,000 chars, shown in a drawer so it doesn't cover content. Notes are searchable (2.8).
- "My snippets": any editor code can be saved with a title (max 50). Restore last code per exercise is automatic and separate.
- All items included in export. No rich text, no images (storage + safety).

### 5.7 Goals
- Only 2 kinds: **Study days per week** (1-7) and an optional **Topic goal** ("Finish Loops by 30 Nov"; shows progress bar and the number of lessons left; date is optional). No XP or minutes goals.
- Goals editable anytime; missing a goal produces neutral copy ("Want to adjust the plan?") and never a failure state.
- Weekly reflection card on first visit of the week: "Last week: 3 days, 2 topics moved forward" (celebrates growth, not misses). Dismissible, "don't show again" option.

### 5.8 Data: export, import, storage risk
- **Why prominent:** Safari deletes all script-writable storage, including localStorage and IndexedDB, after 7 days of Safari use without user interaction with the site [V webkit.org]; home-screen web apps are treated differently [V]. Private windows and cleared site data also wipe it. Request `navigator.storage.persist()` where supported [M].
- **Export:** button "Download my progress" -> file named `learn-python-dsa-progress-YYYY-MM-DD.json`. Contents: `{ "app": "...", "schemaVersion": 1, "exportedAt": ISO, "settings": {}, "events": [], "progress": {}, "notes": {}, "bookmarks": [], "snippets": [] }`.
- **Import:** drag/drop or file picker; validate schema and size (< 5 MB), show a summary ("47 study days, 12 topics, 9 notes"), choose **Merge** (default; keep the newer per item) or **Replace**; always auto-backup the current state into a downloadable file before replace. Errors in plain language.
- **Transfer code** for phone <-> laptop: optional copyable compressed base64 string and QR for small data; fall back to file for large notes [M].
- **Backup nudges:** after 7 days with new progress and no backup, show a small, dismissible banner on the Progress page (not modal): "Back up your progress? It only takes a click." Snooze 14 days. Show last backup date in Settings. If localStorage reads empty but an old "backup exists" flag was never lost, show "Looks like your progress was cleared. Import a backup?"
- Cross-tab safe writes (storage event); versioned schema with migrations; try/catch every access (quota, private mode).

## 6. Visual design directions
Both: warm, human, not primary-colour toy, not corporate blue/white SaaS. Both treat dark as a designed theme. All contrast ratios computed with the WCAG relative-luminance formula (script run).

Sizes: body 18/1.6, h1 36, h2 26, h3 20; code 15-16/1.5; letter-spacing +0.01em body; user "Roomy" option applies 0.12em letter / 0.16em word spacing (the WCAG 1.4.12 ceiling [V]) and layout must survive it.

Icons: 2px stroke, rounded caps, a small set of hand-drawn tool motifs (wrench, pencil, gear) for topics. Topic colors are 6 hues of equal luminance used only as tab-like stripes alongside icon + name.
**Motion:** snappy mechanical: 120-180ms ease-out, small 2-4px press and slide, "click into place" micro-bounce on completing a node (one 250ms overshoot). Animation stage uses linear 300-600ms tweens between steps. Celebrations: a 1.5s stamp ("DONE" stamp thud) instead of confetti. Under `prefers-reduced-motion: reduce`: no tweens, no bounce, no stamp animation, state changes are instant with outline/label changes.

Borrow from B: the constellation graph view for the DSA prerequisite map only.
Guardrails: no mascot with emotions; one optional neutral "helper" glyph max. Avoid babyish rounded-everything and primary-colour explosions. Tone of copy: plain, warm, short.

## 7. Accessibility checklist (must pass before launch)
**Structure and content**
- [ ] One `<h1>` per page, ordered headings, landmarks (`header`, `nav`, `main`, `footer`), skip link first.
- [ ] Page language set; lessons use plain language; jargon defined on first use + glossary [V BDA].
- [ ] Alt text/long descriptions for every diagram; each animation has a text transcript of all steps ("View steps as text").
- [ ] Don't rely on color alone (1.4.1): states use icon + text + shape.

**Contrast and text (1.4.x)**
- [ ] Text >= 4.5:1, large text >= 3:1; UI components and focus indicators >= 3:1 (1.4.3, 1.4.11) in light and dark.
- [ ] Text resizes to 200% without loss; reflow at 320 CSS px with no 2-D scroll except for code blocks and the scrubber stage (1.4.4, 1.4.10).
- [ ] Text spacing override survives: line-height 1.5, paragraph 2x, letter 0.12em, word 0.16em (1.4.12) [V]; test with a bookmarklet.
- [ ] Hover/focus content (glossary popovers, tooltips) dismissible, hoverable, persistent (1.4.13).
- [ ] `rem`-based sizing; body never under 16px.

**Keyboard and focus (2.1, 2.4, 2.5)**
- [ ] Everything operable by keyboard; **no keyboard trap**, including the code editor (Esc then Tab) (2.1.2) [V].
- [ ] Single-character shortcuts: off/remap/focus-only (2.1.4) [V].
- [ ] Visible focus, 2px offset ring in primary color, >= 3:1 (2.4.7) and not hidden under sticky headers or the phone run-bar (2.4.11 Focus Not Obscured, WCAG 2.2) [V list].
- [ ] Target size >= 24x24 CSS px everywhere (2.5.8 AA, WCAG 2.2) [V]; **our standard is 44x44 on touch**.
- [ ] No drag-only interactions: scrubber and reorder exercises have click/keyboard alternatives (2.5.7) [V list].
- [ ] Consistent help location across pages (3.2.6) and no cognitive-test authentication (not applicable: no accounts).
- [ ] Redundant entry avoided: never ask for the same info twice (3.3.7).

**Motion (2.2.2, 2.3.x)**
- [ ] Nothing flashes more than 3 times per second (2.3.1).
- [ ] No autoplay; anything moving > 5 s has pause/stop/hide (2.2.2) [V].
- [ ] `@media (prefers-reduced-motion: reduce)` removes parallax, bounces, tweens, confetti and replaces with instant state changes; also an in-app override that wins [MDN: the feature signals the user wants motion removed, reduced or replaced; M].
- [ ] No timed tasks by default (2.2.1); optional timers can be extended or off.

**Screen readers and structure**
- [ ] Player buttons have names ("Play animation", "Step forward"); Play/Pause uses `aria-pressed` or swaps its label, not both.
- [ ] Scrubber has `aria-valuetext`. Narration in a polite live region only on user actions.
- [ ] Heatmap, mastery rings and charts have table equivalents.
- [ ] Editor: `aria-label`, error summary announced via `role="alert"` on Run failure, line number in text.
- [ ] Status messages (saved, copied, exported) via `role="status"` (4.1.3).
- [ ] Forms (import, settings) have labels, error messages tied by `aria-describedby`.

**Reading and cognition**
- [ ] Left aligned, no justification, no all-caps paragraphs, no italic emphasis [V BDA].
- [ ] Line length 50-75 characters; short paragraphs; 25-word sentence target [V].
- [ ] Optional reading font and spacing controls; offer cream/pale backgrounds (theme "Warm" is default) [V Dyslexia Scotland: pale backgrounds can help some].
- [ ] No distracting animations beside reading text.

**Testing plan:** axe-core in CI; keyboard-only run-through of every flow; NVDA + Firefox, VoiceOver iOS Safari, TalkBack; 200% zoom; 320px; Windows High Contrast / forced-colors (borders must survive); prefers-reduced-motion on; text-spacing bookmarklet; one test session with a dyslexic reader and with a 10-year-old if possible.

## 8. Anti-patterns to avoid
**Gamification and pressure**
- Streak loss framing, red "0", countdown "streak ends in 3 hours", streak repair/freeze as a purchasable thing. Children show mastery avoidance, continuity anxiety, and "I can't lose my streak!" [V ACM IDC study].
- Guilt mascots ("evil bird"), disappointment copy, "it misses you" messaging [V].
- Hearts/lives that block learning on mistakes; paywalled lives [V Sololearn].
- Leaderboards and percentile comparisons (and they'd need a backend).
- XP inflation, level numbers detached from skills, daily quests that force trivial tasks.
- Engagement-only metrics: raw time-on-site or "sessions" as the headline [V Duolingo changed away from this].
- Infinite scroll, autoplaying next lesson, "one more" nudges.

**Learning UX**
- Locking content behind sequence with no escape hatch.
- Timers on beginner exercises; speed-run scoring.
- Showing the solution automatically after N failures, or blurring it (readable by SR).
- Error messages that dump raw Python tracebacks only, or that blame the learner.
- Auto-playing animations; unskippable intros; confetti on every click; sound defaults on.
- Animations without step-back or without text equivalent.
- Hover-only tooltips; tiny controls (< 24px); drag-only scrubbers.
- Huge walls of text; justified text; ALL CAPS; low-contrast grey on grey code comments.
- Reset buttons without undo; Run clearing output on edit.

**Data and trust**
- Silent localStorage dependence (no export, no warning about Safari's 7-day deletion [V]).
- Cookie banners or consent walls: not needed with no tracking. If analytics are ever added, they must be privacy-first and off for kids by default.
- Asking for age, email, or name. Optional nickname stored locally only.
- Dark patterns on exit: confirmation shaming ("No, I don't want to learn"), pre-checked boxes, hidden "clear data".

**Visual**
- Babyish: bubbly rounded mascots everywhere, rainbow primaries, comic fonts. Corporate: grey cards, blue gradient hero, stock illustrations. Both fail the 10-to-adult brief.
